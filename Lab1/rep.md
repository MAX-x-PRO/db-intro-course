## 1. Короткий виклад вимог

### Призначення системи
Система призначена для проєктування, обліку та аналізу ефективності виробничих ланцюжків на автоматизованих заводах. База даних дозволяє відстежувати розміщене обладнання, розподіл ресурсів, рецепти крафту та загальний енергетичний баланс виробничих ліній.

### Дані, що зберігаються в системі
* Інформація про виробничі лінії та їх географічне розташування на карті.
* Довідник типів промислового обладнання та їх базові енергетичні характеристики.
* Конкретні екземпляри побудованих машин у світі з індивідуальними налаштуваннями швидкості та енергоспоживання.
* База рецептів із часом виготовлення та базовими витратами енергії.
* Перелік усіх ігрових предметів, сировини та побічних продуктів.
* Детальний склад кожного рецепта (вхідні компоненти та вихідна продукція).

### Бізнес-правила
1. Кожна виробнича лінія розташована в певній локації та об'єднує набір конкретних машин.
2. Кожна машина у світі належить до певного типу обладнання (наприклад, *Плавильня*, *Конструктор*, *Асемблер*), може виконувати не більше одного призначеного рецепту і належати рівно одній виробничій лінії.
3. Користувач може індивідуально змінювати множник швидкості та множник енергоспоживання для кожної окремої машини.
4. Один рецепт може вимагати кілька різних вхідних предметів і виробляти один або декілька вихідних предметів.
5. Один і той самий предмет може створюватися за різними рецептами.

```mermaid

    Machine_Types ||--o{ Machines_In_World : "define type"
    Recipes ||--o{ Machines_In_World : "used on"

    Items ||--o{ Recipe_Items : "included in"

    Factory_Line {
        uuid id PK
        varchar(50) location
        varchar(50) factory_line_name "UNIQUE"
    }

    Machine_Types {
        int id PK 
        varchar(50) machine_name "UNIQUE"
        int energy_production
    }

    Machines_In_World {
        uuid id PK 
        int machine_id FK 
        int recipe_id FK 
        uuid factory_line_id FK 
        numeric craft_speed_mult
        numeric energy_consume_mult
    }

    Recipes {
        int id PK
        varchar(50) name "UNIQUE"
        numeric base_craft_time
        int req_energy
    }

        int id PK

    }

    Recipe_Items {
        int recipe_id PK,FK

    }
   ```

## 3. Список сутностей та їхніх атрибутів

### 1. `Factory_Line` (Виробничі лінії)
Зберігає інформацію про логістичні вузли або цехи заводу.
* `id` UUID, **PK** — унікальний ідентифікатор виробничої лінії.
* `location` VARCHAR(50) — назва біому або зони на карті, де розміщено виробництво.
* `factory_line_name` VARCHAR(50) — назва виробничої лінії.

### 2. `Machine_Types` (Типи обладнання)
Довідник доступних у грі будівель.
* `id` INT, serial, **PK** — унікальний ідентифікатор типу машини.
* `machine_name` VARCHAR(50) — назва будівлі (наприклад, *"Smelter"*, *"Constructor"*, *"Coal Generator"*).
* `energy_production` INT, default: 0 — кількість енергії (у МВт), яку генерує машина (актуально для генераторів; для споживачів дорівнює 0).

### 3. `Machines_In_World` (Екземпляри машин у світі)
Конкретні будівлі, розміщені гравцем на виробничих лініях.
* `id` UUID, **PK** — глобальний унікальний ідентифікатор побудованої машини.
* `machine_id` INT, **FK** — посилання на тип будівлі в `Machine_Types`.
* `recipe_id` INT, **FK** — посилання на поточний активний рецепт у `Recipes`.
* `factory_line_id` UUID, **FK** — посилання на лінію `Factory_Line`, до якої підключено машину.
* `craft_speed_mult` NUMERIC(10, 2), default: 1, NOT NULL — множник швидкості роботи (розгін/уповільнення).
* `energy_consume_mult` NUMERIC(10, 2), default: 1, NOT NULL — множник споживання електроенергії відповідно до розгону.

### 4. `Recipes` (Рецепти крафту)
Довідник технологічних процесів переробки ресурсів.
* `id` INT, serial, **PK** — унікальний ідентифікатор рецепта.
* `name` VARCHAR(50) — назва рецепта (включно з альтернативними варіантами).
* `base_craft_time` NUMERIC(10, 2), NOT NULL — базовий час одного циклу виробництва в секундах.
* `req_energy` INT — базове споживання енергії для виконання рецепта (у МВт).

### 5. `Items` (Предмети та ресурси)
Довідник усіх матеріалів, деталей та рідин у системі.
* `id` INT, serial, **PK** — унікальний ідентифікатор предмета.
* `name` VARCHAR(50), NOT NULL — назва ресурсу або деталі.

### 6. `Recipe_Items` (Склад рецептів)
Асоціативна сутність, що визначає, які предмети споживаються та виробляються в межах кожного рецепта.
* `recipe_id` INT, **PK**, **FK** — посилання на рецепт у `Recipes`.
* `item_id` INT, **PK**, **FK** — посилання на предмет у `Items`.
* `is_input` BOOLEAN, **PK** — прапорець напрямку: true, якщо предмет є сировиною (вхід), false, якщо предмет є продуктом крафту (вихід).
* `quantity` INT — кількість одиниць предмета за один цикл крафту.

## 4. Пояснення зв'язків між сутностями

1. **`Machine_Types` — `Machines_In_World` (Один-до-багатьох, `1:N`):**
   Один тип обладнання (наприклад, *"Асемблер"*) може мати безліч фізичних копій, побудованих у світі. Водночас кожна конкретна машина у світі належить строго до одного типу обладнання.
2. **`Factory_Line` — `Machines_In_World` (Один-до-багатьох, `1:N`):**
   Одна виробнича лінія складається з багатьох машин, об'єднаних спільним технологічним завданням. Кожен окремий екземпляр машини закріплений за однією конкретною лінією.
3. **`Recipes` — `Machines_In_World` (Один-до-багатьох, `1:N`):**
   Один і той самий рецепт може бути призначений одночасно на десятки однакових машин для масштабування виробництва. Кожна машина в певний момент часу виконує лише один обраний рецепт (або `NULL`, якщо це генератор або рецепт не обрано).
4. **`Recipes` — `Items` через `Recipe_Items` (Багато-до-багатьох, `M:N`):**
   Один рецепт використовує багато різних предметів і може видавати декілька результатів, а один предмет може брати участь у багатьох різних рецептах як інгредієнт або готовий продукт. Зв'язок реалізовано через асоціативну таблицю `Recipe_Items`.

## 5. Припущення та обмеження моделі

* **Унікальність ролі предмета в рецепті:** Додавання атрибута `is_input` до складеного первинного ключа `(recipe_id, item_id, is_input)` у таблиці `Recipe_Items` дозволяє моделювати замкнені цикли (наприклад, рецепти з використанням пакувальної тари, де порожня каністра є і вхідним ресурсом, і побічним виходом).
* **Цілочисельний облік об'ємів:** Атрибут `quantity` має тип `INT`. Припускається, що рідини та гази (вода, нафта, азот) зберігаються в базі у масштабованих одиницях (наприклад, у мілікубометрах, щоб уникнути похибок округлення при обчисленнях.
* **Локалізація налаштувань машин:** Множники швидкості та енергоспоживання зберігаються на рівні `Machines_In_World`, а не `Machine_Types`, що дозволяє налаштовувати розгін індивідуально для кожної будівлі на лінії без впливу на решту заводу.
* **Генератори енергії:** Для машин, які виробляють електроенергію, поле `recipe_id` у таблиці `Machines_In_World` може набувати значення `NULL` або посилатися на умовний рецепт спалювання палива.
* **Обмеження цілісності даних:**
  - Кількість предметів у рецепті (`quantity`) та базовий час крафту (`base_craft_time`) мають бути строго більшими за нуль
  - Множники `craft_speed_mult` та `energy_consume_mult` повинні бути додатними.
  - Показники споживання (`req_energy`) та генерації (`energy_production`) енергії не можуть бути від'ємними
